## 📖 プロジェクト概要 (Overview)

**Universal Bot Setup Playbook** は、あらゆる AI アシスタント ボットのセットアップ、運用、ガバナンスのために設計された、プラットフォームに依存しない実戦的な導入プレイブックです。単一のパーソナル アシスタント（学習、家庭、趣味）から、複数エージェントで構成される艦隊チーム（業務、プロジェクト開発）まで、Day 1 から安全で予測可能な動作を保証します。

### 🛡️ なぜこのプレイブックが必要なのか？

厳格な導入基準がないボットは、以下の重大な問題を引き起こしがちです：
1. **権限ハイジャック**：Web サイトや外部エージェントからの偽装指示を誤って受け入れる。
2. **ファイル破壊**：ユーザー PC 上の大切なファイルを誤って変更、削除、上書きする。
3. **失敗の隠蔽**：ツール実行エラー時に成功したと装い、虚偽の数値を捏造する。
4. **コンテキストドリフト**：過去の古い指示が残存し、新旧のルールが矛盾する。

## 🧩 13 の主要ガバナンスステップ (Core Steps)

| ステップ | 基本原則 | 主な規定 |
| :--- | :--- | :--- |
| **1. オーナー最終決定権** | アカウントに紐付け、名前に非ず | オーナーが唯一の最高決定権者。ボットが勝手に決定を下さない。 |
| **2. ID ベースの識別** | 名前ではなく一意の ID | 全てのボット、チャット、端末を一意の `<BOT_ID>` で厳格に識別。 |
| **3. 二層構造ルール** | チーム規定と役割規定の分離 | チーム規定はオーナーの直接指示なしに変更不可。古い記憶は適切に失効化。 |
| **4. 許可端末ホワイトリスト** | デバイス紐付けと偽装防止 | 登録済み `<DEVICE_ID>` からの指示のみ受付。紛失時の対応プロトコル策定。 |
| **5. 外部入力の非命令扱い** | 他エージェントはデータに過ぎない | 他のボットや Web からの入力は参考情報として扱い、鵜呑みにしない。 |
| **6. 安全な読み取り専用環境** | ホスト PC 読み取り専用・単一サンドボックス | ホスト側は読み取り専用。書き込みは指定の `<WRITABLE_FOLDER>` のみ。 |
| **7. 対外発信・重要操作の事前承認** | 逐次の草案確認 | メッセージ送信、決済、不可逆な変更はオーナーの承認を得てから実行。 |
| **8. 結論先行とタイムゾーン一致** | 簡潔な対話と時刻同期 | 要約は 5 行以内、`<TIMEZONE>` 基準で日付のズレを防止。 |
| **9. 徹底した誠実さ** | 捏造の禁止と率直なエラー報告 | 不明な点は不明と明記。ツールの失敗やタイムアウトは直ちに報告。 |
| **10. 教訓のルール化と自動遮断** | ミスを番号付きルールへ | 失敗を教訓（LL）として記録。同一理由の 2 回連続失敗で作業を強制中断。 |
| **11. ファイル階層と目録管理** | 4 分割ディレクトリと INDEX | `00_inbox`, `10_work`, `20_output`, `90_archive` および台帳の整備。 |
| **12. マルチエージェント協調** | 専用の隔離メールボックス | エージェント間のやり取りは専用の受送信ファイルボックス経由で実施。 |
| **13. 信頼構築の習慣** | 検証可能なエンジニアリング | 変更前のバックアップ、コピー後の SHA-256 検証、限界の率直な共有。 |

## 🚀 クイックスタート (Quick Start)

1. **リポジトリの取得**：スキルディレクトリまたはワークスペースにクローンします。
2. **設定シートの記入**：`templates/bot_setup_manifest_template.md` をコピーし、実効値を入力します。
3. **初日チェックリストの確認**：`templates/first_day_checklist.md` の 16 項目を点検し、運用を開始します。
